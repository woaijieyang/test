## 最直接的控制缺陷：合法前缀可以走离当前参考点

GuardedPrefix.propose只接收preview(action)，其切换条件只有proposal_rejected或source_exhausted。full_compile只检查来源身份/初态，未验证动作片段与每个必需参考点的对应；ordered.execute在参考点未满足时仍持续消费整个官方动作序列。因此“动作合法”被误当成“对当前子任务有效”的充分条件。

## 状态剪枝补充：静态控制流审查

本次只读取实现和既有测试源，不执行搜索/模拟器/测试。action_space.py SHA50c7e0c10f52c666202031cc2ae2d45ab8e79008fae329a86fb595b118263d04与295分析所绑定的冻结planner一致。

1. 当前Pareto剪枝并非单纯“保留过多无用状态”：只在相同完整key上，当旧标签cost和depth均不大于候选时才拒绝候选；反向支配时移除旧active label。旧标签从heap再次弹出会跳过。若原生状态与key确实足以决定后续，且任务有动作数量上限，这个双条件有必要。现有test_cheaper_longer_label_cannot_prune_shorter_budget_feasible_label给出了便宜长路线耗尽剩余步数、较贵短路线仍可到达的合成反例。本次仅审阅测试源，未将其当作新运行结果或原生完备性证明。因此不建议为了提速直接退回单best-cost硬剪枝。

2. exact_state_key保留xyz/xyzw所有float.hex位及reference_index/完整Context；它没有消除q与-q或带符号零的表示冗余，也没有证明任何近似姿态在native restore/step后具有相同后继。数学上旋转等价不能直接替代原生转移等价。295日志缺完整展开状态集，无法据当前源码估计重复标签数量或恢复条数。greedy循环监控仍使用rounded_pose_key；它限制greedy尝试并转入搜索，不直接作为精确搜索的visited键，两者不能混淆。

3. 启发式distance/forward_m针对的是目标中心，而到达谓词为distance<=goal_radius。由代码可直接得出：在0<distance<=0.25的已达目标区域内，剩余任务代价为0，而现有h仍>0；故不能称其为到达区域代价的可采纳启发式。这是既有两版共同设置，不是解释295退化的新增差异，当前代码也明确未声称最优性。将参考半径纳入距离下界是候选改进，但仅改为max(distance-radius,0)/step仍不足以证明一致性：原生台阶/高度投影及转向边必须满足相应进度与代价关系。未经实际条件证明，不借用A*/AMRA*理论保证。

4. 60秒判断在heap弹出/到达检查前，以及动作枚举中执行；因此达到墙钟限制时队列非空不代表任务不可达。max_plan_actions达到时记录depth_limited，前沿结束报告预算耗尽；真实空前沿另报FRONTIER。当前仅有汇总failure而无唯一预算触发分支和完整标签日志，旧295的148/147归因保持“观测阈值+冻结控制流”，不提升为反事实恢复证明。
