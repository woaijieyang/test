## Role hierarchy and operational scope

P0 defines responsibility, source authority, unavailable observations and output ownership. P1 defines interpretation, grouping, five-element evidence, predecessor-to-successor prerequisites, whole-route checks and bounded repair/recheck delivery. L0–L6 remains one Reviewer P1 item. P2 executes within its named P1 parent when a relation is present: it identifies the trigger, concrete operation, protected meaning and return checks. It is not a keyword rule, an extra model call or an exemption from other checks.

Existing role clauses remain mapped. The refinement makes previously terse P2 operations executable: repeated-event identity and real returns; local corrections; conditional viewpoints; same-event endpoint refinement; lexical function; approximation/state changes; target/space/count binding; temporal scopes and compatible branch continuations. Reviewer operations remain independent evidence checks rather than a copy of generation instructions.

Source order means source-supported execution order, not surface sentence order. An unchanged candidate can legitimately pass after an unsupported objection is rejected. Explicit repair phase requires its existing repair envelope even with no findings. Source-required STOP must be restored when lost; only unsupported new stops are prohibited. Grammatical edit permission is distinct from the evidential strength required for a blocking Finding. All teaching cards are projections with their own wrappers; the active Runtime Schema remains authoritative.

## Actual dynamic teaching policy

Ten fixed Core cards remain detailed in stable order. Generator receives two to four Dynamic cases; the first two have complete source, candidate, five-element audit and handoffs. Reviewer receives the corresponding pairs in the same order plus zero to two diagnostics; its first two paired cases contain the full review evidence.

Remaining cards retain the complete original source and candidate. Generator summaries preserve every stage, all five meanings, exact condition/ending evidence, stage-local source quotes, carryover and complete handoffs. Reviewer summaries preserve all source requirements and their indexed evidence, every actual finding and repair/protection, stage meanings and handoffs. Only duplicated process narration and repeated layer conclusions are summarized; no word-length truncation or guessed evidence selection occurs. A summary is not advertised as a complete response object. Projection deep-copies library data.

The same selected IDs and detail policy apply in initial/repair and review/recheck. This change does not rank different examples, increase counts, drop Core to fit an assumed budget or run a model-based summarizer. Explicit production IDs obey the same count, source uniqueness and ordered-pair constraints; explicit `all` is offline export, not a production bundle.

## Isolated structural protection

The common protocol stays byte-identical. RxR Host dispatch adds two mechanical checks on both initial and repaired accepted candidates: each adjacent handoff exactly once in order, and a nonempty supported Target explanation/evidence. A target may be a bounded movement or orientation, not necessarily a room or object. These checks reject incomplete audit structure; they do not invent targets or verify entailment. Reviewer independently assesses executable text, not the Generator audit.

The production Host verifies the paired Reviewer IDs against the frozen Generator order. All new RxR helpers participate in RxR task-level fingerprints. R2R does not load their rules or cards; actual R2R prompts/schemas/selections are compared against the immutable checkout, including existing interleaved-profile regressions.
