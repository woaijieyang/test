# RxR rule maintenance and content lock

RXR_MAINTENANCE_ONLY_DO_NOT_INJECT

本文件仅供维护者阅读，不由 Compiler、Host、检索器或任何角色 Prompt 加载。冻结状态不写入规则标题，不进入模型输入，不改变规则优先级。当前只补充两份 RxR 角色规则中的操作；架构、CLI、Schema、模板、完整动态输入、选例数量、排序、Renderer 和 R2R 均保持原样。P0 原文不变，P1/P2 标题和 L0–L6 的框架位置不变。

## 状态必须准确解释

- `frozen_contract`：保护明确的、带适用条件的语义不变量，例如原文规定的停止不能被删除、局部纠正不能抹去无关动作。这不是“该规则绝对提高导航 SR”的认证，也不是对全部场景的无条件行为承诺。
- `locked_pending_validation`：本次补齐的操作文字已定稿并内容锁定，不能为了文风或某一条导航失败反复改写；真实模型执行效果和导航收益仍待对照验证。
- `frozen_gain`：只有固定输入、模型、模板、格式和评估设置的规则级对照、收益保留与回归审查可以支持。现有文件没有这种因果证据，因此当前此集合为空。历史成功任务只提供保护方向，不自动给单条规则授予此状态。

`provenance/rxr_rule_lock.json` 保存每份角色规则及每个章节的 SHA-256、九项受保护不变量、十六处新增操作和证据定位。`tests/test_rxr_rule_lock.py` 只读验证锁定内容、已有段落保留、作用域和模型输入边界。测试不调用模型，不把关键词检查伪装成语义正确率。

## 已有能力保护

| 保护项 | 保留的行为 | 禁止的过度保守变化 |
|---|---|---|
| 有价值的分组 | 支持的完成事件、独立后继与清晰交接可以形成有效 SPLIT；单一连贯事件也可 KEEP | 默认 KEEP、默认合并、禁止合法重组，或按数量鼓励 SPLIT |
| 必要入口 | 唯一可继承状态可以省略重述；计数、参照或身份确有需要时补最短锚点 | 全面新增或全面删除 From/After/At |
| 纠正作用域 | 应用明确纠正后的方向或对象，保护无关动作 | 同时执行纠正前后动作，或删掉同句中未被纠正的路线 |
| 源规定停止 | 恢复真实 STOP/WAIT，保留中间与最终范围 | 边界自动加 STOP，或以禁止新增 STOP 为由拒绝恢复原文 STOP |
| 完整有效源 | 使用原文规定的终态、合法最终趋近和可解释路线 | 因缺少视觉、地图、厘米动作或未写 STOP 就拒绝 |
| 独立、局部审核 | 以实际源/候选证据审核，允许合法不同措辞和分组 | 根据导航失败、偏好或模板 Verdict 阻断 |
| 选择性返修 | 正确拒绝无依据建议时，候选英文可以不变 | 强制改字、全局重写，或把已恢复要求继续报为缺失 |

历史源观察包括 942/51571、6445/25512、9298/47547、4932/69820 的具体返修链，以及 10407/83394、6043/75568、8277/117379、7533/96039 的合法能力保护。9975/84498、7282/30051 说明“文本已修正”与“导航成功”必须分开。只在本维护记录保留任务定位，不将评测路线、成绩或轨迹放入 Prompt 或检索模板。

## 维护边界与解锁条件

本次十六处补充全部放在既有章节末尾，旧规则段落原样保留。Generator 的局部纠正、近似规则和 Reviewer 的重复、纠正、局部缺陷范围等已有有效表述不重写。全部正文锁定是为了防止后续漂移，不是声明未经测试的新操作已有绝对收益。

后续只有以下依据可以申请解锁：完整源文/候选显示可复现的规则冲突或语义反例；或者固定条件的对照表明新增退化。先说明冲突、最小改动、合法反例和可能受影响规则，再审阅具体差分及更新锁定记录。不能直接运行自动工具重写 Hash 来让失败测试通过；普通 CI 不更新规则、锁或预期快照。

分隔空白、进度记忆、动作预算和碰撞原因不转成新的语义禁止。未使用本次样本新建模板，不改检索、不改 Actor，不将 GT/轨迹作为运行时事实。独立共享合同与 RxR Shared Rules 保持不变，两角色操作不得覆盖它们。

## 校验含义

验收包括：角色文件和每章节内容锁；原句与 P0/标题保留；运行代码/所有模板/R2R 原字节保护；移除且仅移除本次角色块后恢复基线四阶段 Prompt；Schema、选例与完整教学保持一致；维护标记不进入 Prompt；原有全仓库回归。规则锁与结构测试不是 LLM 语义实验，更不是导航因果实验。需要真实证据时再提升收益状态，当前不作绝对有效承诺。
