# 阶段文档规范

本目录仅规则及plan/conclusion。一阶段一对文档，全部子任务集中，不新增progress/check/report。
命名YYYY-MM-DD-当天序号-plan或conclusion-具体中文概括.md，Asia/Singapore首次创建日期；两类型共用当天连续序号，创建前重新核对。概括8–18字符。跨日保留名字，正文记录真实时间。
plan包含事实/假设、目标边界、基线输入、实验变量/对照、子任务依赖/入口/验收、资源及停止条件。变更记录时间、原因、授权及可比性影响，不能事后重写原门槛。
conclusion引用plan并明确进行中/完成/失败/阻塞/暂停，记录实际步骤、命令、身份、耗时、失败与修复、分母、复算、验收、限制及发布状态。保留负结果及更正。
原始日志/响应/图像/轨迹/JSON保存在outputs，文档引用路径/hash。不把接口、CPU或路径存在当导航正确，不把建议当授权。

本次明确例外：用户于2026-10-15要求将导航连通性阶段单独写conclusion，故新增2026-10-15-1-conclusion-导航连通性专项验收.md，关联原活动plan；不再为该专项创建额外进度文件。
