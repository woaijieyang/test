# R2R 运行边界与工作流稳定性补齐

## 本轮基底与范围

本轮从 `d07674e382318cdfc832b6ecd7bf96424fc58d7d` 继续，不覆盖此前已经完成的目录迁移、来源重放、最小改写规则和专用教学筛选。上一轮完整实施记录见 `docs/R2R_MINIMAL_REPORT.md`。运行时位于 `host/r2r/`，作者工具位于 `tools/r2r_authoring/`，测试位于 `tests/r2r/`，未恢复根目录旧包。

本轮不再增加P2、不修改125份普通模板和四份阶段教学输出，不改变排名权重、选例数量、Actor、Renderer、Adapter或公共Schema。只补实际入口的拒绝边界、阶段教学校验和CI职责隔离。

## 已修复的问题

### 1. 显式模板ID绕过专用适用条件

自动检索已有 `required_query_facets`，但显式传入 `selected_ids` 的编译路径此前仅核对身份及数量。现在编译器将实际来源传给 `validate_selection`，同样验证专用案例适用性；普通路线不能通过手动ID注入返回或分支专用教学。未知来源不能声称专用适用。无关专用案例正常不入选，不触发原文回退；外部强制指定不适用ID属于配置错误并拒绝。显式离线 `all` 模式仍保留完整库查看能力，不用于普通在线请求。

### 2. 规则映射只检查前缀而未核对真实条款

教学索引现在同时读取Generator及Reviewer的实际规则文本，验证ID确实存在。缓存键包括索引与规则文件的原始字节，修改当前规则不能沿用旧映射缓存。未知规则、跨角色链接和畸形适用条件不再静默进入请求。

### 3. G1/R1阶段教学直接加载JSON而未验证协议

新增 `host/r2r/phase_teaching.py`，只在R2R的repair/recheck阶段使用。检查非空案例、唯一ID、角色/阶段/合成来源身份、真实规则链接、原始文本、R0输入以及G1/R1完整输出；使用现行 `host.protocol` 而不是另造Schema。刻意错误的R0仍是可反驳输入，不被当成语义金标。返回值为防御性复制，缓存随磁盘字节和规则字节失效。此运行模块纳入对应阶段冻结清单，运行时不导入作者工具。

### 4. 旧RxR写入CI将批准的R2R演进误报为污染

基底提交上的 `Isolated RxR integration and validation` 曾用 `da277a0…` 的旧R2R策略作对照，因而对当前已批准的R2R变动报告隔离失败。本轮不通过回滚R2R或放宽语义检查解决。

检测到当前R2R作者清单的树时，RxR任务改为只读验证：用该次事件的不可变 `GITHUB_SHA` 建立构建前对照；RxR作者资产只检查、不重写；不刷新其他Profile的清单、不改写历史验证记录、不提交或推送；最后要求工作树无变化并通过包完整性检查。历史RxR专用树仍保留原来的作者发布路径。工作流本身变化也会触发验证，避免修完CI却没有运行。测试发现明确使用仓库顶层，唯一缺失的仓库外夹具仍单列而不计通过。

### 5. 完整RxR测试入口与历史回放环境隔离

目标分支的整条CI补测发现两个测试入口问题：顶层发现测试时没有加入旧测试所需的tests导入目录；构建前后对照复用了历史RxR选择回放的R2R_BASELINE_DIR变量。本轮为测试进程显式补入tests路径，并将构建对照单独命名为R2R_BUILD_BASELINE_DIR，保留历史选择回放的固定提交检查，不放宽检查也不删除失败测试。

回归测试会在全新解释器执行工作流原文中的发现测试前置代码，检查未预期导入错误；最终CI必须执行工作流内完整测试，而不仅运行另一套入口的测试。实际未运行的仓库外夹具仍单列。

## 验证口径

当前全量回归为380项，包括本轮31项新增边界测试；外部 `manage_release.py` 测试缺失单列。真实结果以 `provenance/r2r_regression_results.json` 为准。

再次对工作簿的1068条来源分别在基底和候选独立进程中重放，每版4272组四阶段请求。两份完整审计文件逐字节相同：选例、Prompt、Schema、固定Core、动态投影、阶段教学均一致。Generator仍为1047条选4例、21条选5例；Reviewer诊断仍为743条选2例、325条选3例。本轮不把合法请求变化当成收益，因为根本没有改变这些合法请求。摘要与输入哈希见 `provenance/r2r_stability_validation.json`。

六份已编译Prompt与基底保持一致；RxR隔离检查仍覆盖205个受保护文件、47来源×4阶段=188组请求以及混合Profile；24条Renderer Smoke、离线四阶段Demo和重复构建继续验证。CI修复会在远端另外验证整条RxR只读流程，不能用单个测试通过代替整条工作流通过。

## 限制

以上都是工程、协议及编译重放验证，没有调用真实LLM或运行导航，不能据此宣称SR/SPL/nDTW改善。固定Core的val_seen来源、缺少路径ID时的家族隔离、真实C10欠分割金标准及持续表面关系的专用对照教学，仍按上一轮记录保留证据边界，不编造完成状态。
